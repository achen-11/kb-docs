# Kooboo Docs Studio 信息架构与页面规划

> 状态：已确认，按阶段实施。
> 适用范围：内网文档编辑平台 `4174`。文档快速预览继续使用 `4173`，稳定生产构建预览继续使用 `4175`。

## 1. 产品定位

`4174` 从单页 Markdown 编辑器演进为 **Kooboo Docs Studio**：以文档编辑为核心，统一管理草稿、图片、Git 版本、构建预览、候选部署和生产发布。

系统不复制完整 Git 客户端或 Kooboo 后台。内容人员看到的是面向任务的“当前改动、提交记录、审核任务和发布记录”；Git、SSH、Kooboo CLI 和部署凭据留在服务端。

## 2. 核心原则

1. 从 `4173` 的编辑链接进入时，直接打开目标文档并进入沉浸式编辑器，不经过工作台。
2. 全局导航只使用两级结构，不增加三层以上树形菜单。
3. 高频编辑与高风险发布分离；编辑器只保留“保存草稿、构建预览、提交改动”。
4. “发布线上”不出现在 Markdown 编辑器中，只存在于发布中心。
5. `4173`、`4175`、Kooboo 候选站和生产站必须使用明确名称和状态，不能混淆。
6. 图片既有独立资源管理页面，也能从编辑器上下文中选择、上传和插入。
7. Git 仍是最终内容源；服务器草稿必须通过提交或撤销重新回到干净 Git 状态。
8. 未接入的能力显示真实的实施状态与依赖，不提供看似可用的假按钮。

## 3. 一级与二级导航

```text
工作台

内容管理
├── 文档编辑
└── 图片资源

改动与版本
├── 当前改动
├── 提交记录
└── 审核任务

预览与发布
├── 构建预览
├── 候选发布
├── 线上发布
└── 发布记录

系统管理
├── 用户与权限
├── 站点配置
└── 操作日志
```

左侧导航展开宽度为 `216–232px`，收起宽度为 `56–64px`。编辑器路由默认进入收起状态，并记忆用户手动选择。

## 4. 路由

```text
/                         工作台

/content/editor            文档编辑器
/content/media             图片资源

/changes/workspace         当前改动
/changes/commits           提交记录
/changes/reviews           审核任务
/changes/reviews/:id       审核详情

/releases/builds           构建预览
/releases/candidate        候选发布
/releases/production       线上发布
/releases/history          发布记录
/releases/:id              发布详情

/settings/users            用户与权限
/settings/site             站点配置
/settings/audit            操作日志
```

兼容旧编辑链接：根路径携带 `?path=docs/...md` 时重定向到 `/content/editor?path=...`。

## 5. 页面职责

### 5.1 工作台

- 继续最近草稿或打开默认文档；
- 显示 `4173`、`4175`、Git 同步、当前改动和候选/生产版本状态；
- 展示待提交、待审核、待验收事项；
- 展示最近编辑、构建和发布活动。

工作台以工作状态和待办为主，不做无业务价值的统计卡片集合。

### 5.2 文档编辑器

- Markdown 原文编辑；
- `4173` HMR 快速预览；
- 编辑区/预览区拖拽调整；
- PC、平板、横屏平板、手机和自适应视口；
- 保存草稿；
- 显式构建 `4175`；
- 后续进入“提交改动”流程。

保存后必须明确显示：草稿已保存、`4173` 已更新、尚未提交 Git、Git 自动同步已暂停。

### 5.3 图片资源

- 文件夹、搜索、分页或虚拟列表；
- 上传、拖拽和剪贴板粘贴；
- 图片详情、URL、尺寸、大小和 Git 状态；
- 查看引用文档；
- 重命名时同步修改引用；
- 删除前引用保护；
- 从编辑器插入 `<DocImage>` 或 Markdown 图片语法。

第一版上传根目录限定为 `cms`、`product`、`en/cms` 和 `en/product`。`home` 资源先只读，避免在本阶段改变 Kooboo 资源类型。

### 5.4 当前改动

- 展示新增、修改、删除和重命名文件；
- Markdown 文本 diff；
- 图片前后对比；
- 单文件撤销和全部撤销；
- 修改说明；
- 生成 Git commit 并推送审核分支；
- 提交或撤销后恢复 Git 自动同步。

### 5.5 提交与审核

- 提交记录显示 commit、作者、时间、文件数、构建和发布状态；
- 审核任务包含 diff、`4175` 预览、构建结果和审核意见；
- 第一版只暴露文档工作流需要的 Git 操作，不暴露 rebase、cherry-pick 等完整 Git 客户端能力。

### 5.6 构建与发布

- 构建预览管理 `4175` release、来源、耗时、日志和历史；
- 候选发布从审核后的 source commit 生成 artifact commit，执行 `kb deploy` dry-run、内网 Kooboo 部署和真实验收；
- 线上发布只接受候选验收通过的同一个 artifact commit；
- 发布记录保存 source commit、artifact commit、`from -> to`、操作人、回执和 HTTP/浏览器验收结果。

## 6. 权限边界

| 能力 | 编辑者 | 审核者 | 发布者 | 管理员 |
|------|--------|--------|--------|--------|
| 编辑、图片、保存草稿 | 是 | 是 | 可选 | 是 |
| 构建 `4175` | 是 | 是 | 是 | 是 |
| 提交改动 | 是 | 是 | 可选 | 是 |
| 审核合并 | 否 | 是 | 可选 | 是 |
| 部署候选站 | 否 | 是 | 是 | 是 |
| 发布生产 | 否 | 否 | 是 | 是 |
| 用户和系统配置 | 否 | 否 | 否 | 是 |

当前共享访问口令只用于内网 MVP。接入生产发布前必须升级为独立用户、角色权限、重新认证和完整审计。

## 7. 前端结构

```text
editor/src/
├── app/                 # router、共享状态、应用 Shell
├── layouts/             # 后台布局与沉浸式编辑布局
├── pages/               # 路由页面
├── features/            # editor、media、changes、releases
├── components/          # navigation、status、diff、feedback
└── api/                 # 按领域拆分的服务端 API
```

第一阶段保留现有 Vue 3、Vite 和 CSS 技术栈，引入 Vue Router；不引入大型 UI 框架，不重写已经验证的保存、构建、路由跟随和预览逻辑。

## 8. 实施阶段

### Phase A：后台骨架与编辑器迁移

- Vue Router；
- 全局导航、顶部状态栏和面包屑；
- 工作台；
- 编辑器迁入沉浸式页面；
- 兼容旧编辑链接；
- 规划页面显示真实待接入状态。

### Phase B：当前改动与 Git 闭环

- 工作区 diff；
- 撤销；
- commit 与推送审核分支；
- 草稿结束后恢复 Git 同步。

### Phase C：图片资源

- 媒体列表、搜索、上传和粘贴；
- 编辑器插入；
- 引用检查、重命名和删除保护。

### Phase D：构建与候选发布

- 构建历史与日志；
- artifact commit；
- `kb deploy` dry-run；
- Kooboo 候选站和自动验收。

### Phase E：生产发布与权限

- 独立用户和角色；
- 生产重新认证；
- 发布回执和线上验收；
- 环境独立部署 baseline；
- 操作日志。

## 9. Phase A 验收条件

1. `/` 登录后显示工作台。
2. 旧的 `/?path=docs/...md` 能无损进入新编辑器路由。
3. 从 `4173` 点击编辑链接仍能直接加载对应 Markdown。
4. 保存草稿、`Ctrl/Cmd+S`、4173 HMR、显式构建 4175、预览路由跟随、冲突检查和拖拽视口全部保持可用。
5. 编辑器不再显示“发布线上”。
6. 图片、Git、候选和生产页面有稳定路由，且只展示真实的阶段依赖与待接入状态。
7. 移动端导航可用，编辑器继续退化为上下布局。
