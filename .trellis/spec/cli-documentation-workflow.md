# Kooboo CLI 文档编写流程

> 适用于 `docs/cli/**` 与 `docs/en/cli/**`。

## 目标

CLI 文档只解决两个问题：Kooboo CLI 能做什么，以及用户应该怎样安全、正确地使用这些功能。

## 唯一功能依据

`/Users/achen/Priv/Yardi/cli` 是 CLI 功能和行为的唯一依据。

README、技能、旧文档和历史记录只能用于发现主题。只要命令、参数、默认值或行为与当前项目不一致，一律以当前项目为准。

## 编写前核验

每一篇正文开始前，先完成内部核验：

1. 确认命令已经注册。
2. 确认命令确实执行了对应功能，而不是占位实现。
3. 确认参数组合、默认值、读写范围和远端副作用。
4. 确认错误提示与恢复方式。
5. 将核验结论保存在 `.local-review/`，不要把核验路径或实现细节写入公开文档。

## 公开正文应该包含

- 功能解决什么问题；
- 使用前提；
- 命令格式和可复制示例；
- 参数含义；
- 本地和远端会发生什么；
- 会覆盖、删除或持续同步远端资源时的明确警告；
- 常见失败原因和恢复方式；
- 与其他 CLI 工作流的链接。

## 公开正文禁止包含

- CLI 源码仓库路径；
- 源码文件名、包目录和代码片段；
- 内部函数、类、类型或调用链；
- CLI 内部使用的 HTTP 接口；
- 为证明结论而展示的实现细节；
- 已注册但当前没有实际效果的命令；
- 仅存在于 README、技能或旧文档、但未被当前项目确认的行为。

## 文档结构

每篇命令型文档优先使用以下结构：

1. 一句话说明用途；
2. 使用前准备；
3. 常用命令；
4. 目标范围或参数说明；
5. 执行结果；
6. 风险和注意事项；
7. 常见组合；
8. 相关文档。

不需要为每篇机械保留全部标题；较短页面可以合并章节，但风险提示不能省略。

## 中英文一致性

- 中文位于 `docs/cli/**`，英文位于 `docs/en/cli/**`。
- 文件路径、标题层级、表格行、命令示例、警告和相关链接保持 1:1。
- 英文是等义重写，不是摘要。
- 同一批次同时修改中英文页面。
