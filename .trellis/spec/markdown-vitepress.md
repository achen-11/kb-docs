# VitePress 文档 Markdown 约定

> 适用于 `docs/cms/**`、`docs/api/**`、`docs/templateEngine/**` 等 VitePress 正文

## 标题与分割线（`---`）

本站主题在 **`.vp-doc` 内标题（`h2`、`h3` 等）上方会渲染一条与分割线同款的 border**。

因此：

| 做法 | 说明 |
|------|------|
| **不要**在 `##` / `###` 标题**紧上方**写 `---` | 会与标题自带 border **叠成两条线** |
| **不要**在标题**正下方**用 `---` 做「收尾」 | 通常多余；下一节若仍是标题，同样重复 |
| **可以**在**纯段落之间**使用 `---` | 上下都不是标题，且需要明显分段时（少用） |

**推荐**：章节之间直接用标题层级（`##`、`###`）分隔，不用 `---` 垫在标题前。

```markdown
<!-- 不推荐 -->
---

## 注意事项

<!-- 推荐 -->

## 注意事项
```

编写或 Review 文档时，若见标题上下有孤立的 `---`，应删掉靠标题一侧的那条。

## 内部编辑要求与公开正文

Boss 反馈、验收标准、写作策略、内容取舍理由等属于**内部编辑上下文**，不得直接写进面向用户的文档正文。

例如，“第一个示例必须足够简单”“不要一次引入搜索、分页和映射”可以作为编辑要求指导文档结构，但公开页面中应直接呈现优化后的示例，不应解释团队为何这样编排。

公开正文只保留对用户有直接价值的内容：

- 产品或语法事实；
- 使用前提、操作步骤和结果说明；
- 技术限制、风险和必要注意事项；
- 帮助用户定位内容的中性导航。

当前公开站点只发布 `docs/en/**`，英文页面位于站点根路径。中文源文件同步维护，暂不发布。具体栏目开关以 `scripts/docs-publish-locale.mjs` 为准；当前 CLI、Product Features 与 `docs/superpowers/**` 内部设计稿不进入公开导航、搜索或页面产物。不要根据历史域名、旧篇数计划或本地文件存在推断发布范围。

避免出现以下内部话术：

- “根据 Boss 反馈……”；
- “为了避免吓走用户……”；
- “不要在第一个示例中……”；
- “我们决定先写……再写……”；
- 对评审过程、修改原因或验收策略的复述。

需要表达内容关系时，改写为用户视角的中性说明。例如用“分页查询使用 `action="paged"`”，不要写“最后再增加分页”。
