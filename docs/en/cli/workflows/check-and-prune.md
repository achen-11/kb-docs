# Compare and clean remote resources

`kb check` compares the local project with the remote site. `kb prune` uses the comparison result to audit drift resources that exist only remotely and deletes them only after safety checks and explicit confirmation.

`prune` is a high-risk maintenance tool, not a formal release step. Publish resources explicitly deleted in Git through [`kb deploy`](./deploy.md). Use `prune` only for old deployment leftovers, abandoned manual resources, or other remote drift.

## Compare resources

```bash
kb check
```

Limit the scope:

```bash
kb check js
kb check page/admin
kb check images/banner.png
kb check module/shop
```

The report separates in-sync, local-only, remote-only, modified, ignored, and failed resources and suggests whether a push or cleanup is appropriate.

## Comparison levels

```bash
kb check --level 1
kb check --level 2
kb check --level 3
```

| Level | Compared data | When to use it |
|-------|---------------|----------------|
| `1` | Resource inventory | Quickly find local-only or remote-only resources |
| `2` | Inventory and metadata | Check resource names, paths, URLs, and related information |
| `3` | Inventory, metadata, and content | Confirm whether same-name resources have identical content before release |

Higher levels read and compare more data. Use level 1 for quick daily checks and level 3 for important releases.

## Output formats and report files

```bash
kb check --format table
kb check --format json
kb check --format silent
kb check --level 3 --output .kooboo/check-report.json
```

| Option | Description |
|--------|-------------|
| `--format table` | Show a readable terminal summary; this is the default |
| `--format json` | Print the full JSON report in the terminal |
| `--format silent` | Do not print the comparison table |
| `--output <path>` | Write the full report to a file |

Local or remote resources matched by `.pushignore` are marked as ignored and are not added to the cleanup plan.

## Preview remote cleanup

```bash
kb prune
kb prune --output .kooboo/prune-plan.json
```

Without `--yes`, `kb prune` only generates a cleanup plan and does not delete remote resources. Limit the scope:

```bash
kb prune js
kb prune module/shop --allow-modules
```

Use a saved, scoped comparison report:

```bash
kb check js --level 3 --output .kooboo/check-report.json
kb prune --report .kooboo/check-report.json
```

When previewing from a report, still confirm its site, project directory, and target scope. Before actual deletion, the CLI reruns a live level 1 comparison and refuses to continue if the report no longer matches the current targets.

## Execute deletion

A full-site `kb prune` is preview-only. Actual deletion requires a target or a report generated by a targeted `kb check`. After confirming the preview:

```bash
kb prune --report .kooboo/check-report.json --yes
```

Or compare and delete a specific scope directly:

```bash
kb prune js --yes
```

Protected resources such as the start page are skipped by default. Add this only when you explicitly need to delete protected resources:

```bash
kb prune --report .kooboo/check-report.json --yes --force
```

`--force` only removes protection from resources such as the start page. It does not remove module protection or the deletion-count limit.

A run deletes at most 20 items by default. If the plan is larger, review the complete plan and explicitly raise the limit:

```bash
kb prune js \
  --output .kooboo/prune-result.json \
  --max-delete 50 \
  --yes
```

Module files are protected by default and cannot be unlocked through a full-site or broad `module` scope. Limit the command to one module:

```bash
kb prune module/shop --allow-modules
kb prune module/shop --allow-modules --yes
```

If the selected scope contains no local module resources, the CLI refuses to delete an entirely remote-only module. Use `kb deploy --apply-deletes` when Git explicitly removes the module resources. Review deletion of an entire remote module separately in the administration UI.

The command fails closed and performs no deletion when:

- a local resource cannot be identified or the local scan fails;
- deletion execution has no target scope;
- the remote module inventory is incomplete;
- the check report belongs to another project or differs from the live comparison;
- a module has no local baseline;
- the item count exceeds `--max-delete`;
- the report and connected site do not match.

## Temporarily specify connection details

`check` and `prune` support:

```bash
kb check \
  --site-url https://example.com \
  --username your-username \
  --password your-password
```

For daily use, prefer a project `.env` that fixes the target site and reduces the risk of a report/site mismatch.

## Recommended workflow

```bash
git status --short
kb check js --level 3 --output .kooboo/check-report.json
kb prune --report .kooboo/check-report.json
# Review the cleanup plan manually
kb prune --report .kooboo/check-report.json \
  --output .kooboo/prune-result.json \
  --yes
kb check js --level 3
```
